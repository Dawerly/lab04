## Варіант 14

`Node(value, children)` — `@dataclass(frozen=True, slots=True, eq=False)`.
Діти зберігаються в tuple; вкладені вузли також незмінні. Модель описує
скінченне ациклічне впорядковане дерево, можливі спільні незмінні піддерева.
Всі вхідні значення мають відповідати анотаціям типів.

Функції в `algorithms.py`:
- `preorder`: значення вузла, потім діти зліва направо;
- `postorder`: діти зліва направо, потім значення вузла;
- `find_recursive`: перший збіг у preorder або None;
- `dfs_preorder_iter`: власний стек; дітей додано у зворотному порядку;
- `bfs_level_order`: черга deque, рівень за рівнем;
- `find_iterative`: пошук із власним стеком;
- `height_recursive`, `height_cached`, `height_iterative`: висота в кількості
  вузлів; порожнє дерево — 0, листок — 1.

Для порожнього дерева обходи повертають порожній результат, пошук — None.
Для рекурсивного обходу крок — той самий алгоритм для кожного дочірнього
піддерева. Для висоти крок — `1 + max(висоти дітей, default=0)`.
Пошук завершується при збігу поточного значення або обходить дітей.
Функції не змінюють дерево; списки/черги в ітеративних алгоритмах локальні.

## Мемоізація

`height_cached` має `@lru_cache(maxsize=None)`. Програма демонструє
`cache_info()` після першого та повторного виклику, а також `cache_clear()`.

За `eq=False` вузли порівнюються й хешуються за ідентичністю об’єкта.
Це дає O(1) ключ кешу без рекурсивного хешування всього дерева. Два окремо
створені вузли з однаковим вмістом мають окремі записи кешу. Повторне
використання того самого піддерева дає влучання вже в першому запиті.
Обходи при цьому відвідують спільне піддерево за кожним входженням.

Для звичайного дерева один холодний розрахунок не має повторних підзадач.
Мемоізація корисна для повторних запитів і спільних піддерев. На прогрітому
кеші повторний запит висоти кореня має O(1) доступ; перший обхід — O(n).
Кеш утримує вузли в пам’яті до `cache_clear()`. Математичний результат
детермінований; статистика кешу змінюється під час викликів.

## Обов’язкова база з документа

У `basics.py` додатково реалізовано:
- чистий рекурсивний тришляховий quicksort з випадковим pivot;
- BinaryNode та рекурсивні preorder/inorder/postorder;
- ітеративні BFS і DFS бінарного дерева;
- Fibonacci з lru_cache і цикл fib_iter, відхилення від’ємних n.

Quicksort створює власний `Random(seed)`: однакові аргументи відтворюють
вибір pivot, глобальний random-стан і вхідна послідовність не змінюються.
Три групи `<`, `==`, `>` обробляють дублікати без рекурсії над рівною групою.
Очікуваний час O(n log n), гірший O(n²). Створюються нові списки; пам’ять
і стек залежать від розбиття, тому найгірший випадок дорожчий за збалансований.
Fibonacci має O(n) підзадач і O(n) пам’яті кешу; fib_iter зберігає дві змінні.
Тут оцінки рахують арифметичні операції, без деталізації великих цілих чисел.

## Ліміт стеку та TCO

`sys.getrecursionlimit()` показує поточний ліміт CPython, зазвичай близько
1000 кадрів. Фактична доступна глибина алгоритму залежить від уже зайнятих
кадрів, генераторів і декораторів. CPython не виконує оптимізацію хвостових
викликів (TCO): хвостова рекурсія також витрачає стек.

Мемоізація зменшує повторні обчислення, але не усуває глибину рекурсії.
Для глибоких дерев використовуйте height_iterative, dfs_preorder_iter,
bfs_level_order та find_iterative. Тест обробляє ланцюжок із 1500 вузлів
ітеративно. Програма не змінює ліміт рекурсії.

У n-арних обходів час O(n); рекурсивний стек залежить від висоти h.
DFS із власним стеком може утримувати багато відкладених дітей,
BFS — цілий рівень. Обидві реалізації обходів повертають список із n значень,
тобто мають додаткову O(n) пам’ять результату. BFS-висота повертає лише число.
